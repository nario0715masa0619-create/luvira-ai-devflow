# AIレビューID 秘密情報保管運用 v1

## 保管区画

AIレビュー専用IDの秘密情報は、`luvira-ai-devflow` の GitHub Environment
`ai-reviewer-custody` にのみ登録する。通常のリポジトリSecrets、コード、Issue、
PR、Actionsログ、チャットには登録・出力しない。

この区画は、保護済みブランチからの利用、正式承認者の利用承認、自己承認禁止、
管理者バイパス禁止を必須とする。

## 鍵を登録する前の確認

以下を全て確認できるまで、GitHub Appの鍵を生成してはならない。

1. App名、用途、対象リポジトリ許可リスト、最小権限が承認済みである。
2. Environment の利用保護が有効である。
3. 生成直後の鍵を、表示・転記・複製せず Environment Secret へ登録できる経路がある。
4. 公開鍵指紋と保管完了記録を、鍵本文なしで独立照合できる。
5. 失効担当者、失効手順、案件インストール解除手順が確認済みである。

一点でも満たせない場合は、鍵を作成せず設計段階へ戻る。

## 登録時の制約

- Secret名は用途を表す固定名とし、値・部分値・Base64・パスを記録しない。
- レビュー実行は保護済みの基盤ワークフローから行い、PR由来のコードや設定を実行しない。
- PRの差分は読み取りAPIで取得する。PRブランチのスクリプトを秘密情報に触れる実行環境で起動しない。
- 実行記録には、対象PR、Context Lock、モデル識別子、時刻、結果だけを残す。

## 短期認証の検証

`Luvira AI reviewer` ワークフローは、秘密情報を参照せずにOIDC信頼経路だけを
検証する。対象は `luvira-ai-devflow` の `main` と当該ワークフロー名に固定される。
この検証が成功しても、外部AI呼出し、PRレビューの提出、秘密情報の取得は行わない。

## 照合と失効

鍵登録後、鍵本文を再表示せず、GitHub上の公開鍵指紋と保管完了記録を別経路で
照合する。不一致、保管先不明、不要な権限、想定外の利用記録があれば、直ちに
Appの案件インストールを解除し、該当鍵を失効する。

新鍵を登録・照合するまで、失効済み鍵の代替運用や既存鍵の再利用をしない。

## 禁止事項

- ブラウザのダウンロード先が検証できない状態での鍵生成
- 鍵をローカル一時フォルダ、Downloads、リポジトリ、Issue、PR、チャットへ置くこと
- 秘密情報に触れられるワークフローでPR由来コードを実行すること
- 鍵保管の確認を、鍵を作成・登録した同一実行主体だけで完結すること
