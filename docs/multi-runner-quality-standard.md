# 複数AI実行・常時品質監視標準 v1

## 目的

ChatGPT、Copilot、Codex、Claude Codeなど、特定のAIの利用上限・障害・品質劣化で
開発全体を止めない。一方で、AIの切替を理由に品質基準や権限境界を緩めない。

## 実行AIの扱い

Kimi/Qwenは低コストの**実装ワーカー**、CodexとClaude Codeは独立した**品質レビュー
ワーカー**として扱う。実装順は案件の `runner-routing-policy.json` で固定し、標準順は
次とする。

1. Kimi
2. Qwen
3. Copilot（必要時の実装退避先）
4. Codex（実装退避先として使う場合も、レビュー役とは別実行IDにする）
5. Claude Code（同上）

退避できるのは `provider_unavailable`、利用上限、タイムアウト、一時障害だけである。
Context Lock不一致、テスト失敗、セキュリティ指摘、ポリシー違反では退避せず停止する。
同じ誤りを別AIで繰り返して通すことを禁止するためである。

各Issueは最大3回、退避は最大2回までとする。上限到達時は監視役が `blocked` と記録し、
次の自動実行は30分後以降に限定する。

## Codex・Claude Codeの二重品質レビュー

Kimi/Qwenが作成したPRは、CodexとClaude Codeの**両方**が独立に `APPROVE` するまで
合格としない。片方でも `REQUEST_CHANGES`、実行失敗、タイムアウト、判定不能なら
fail-closedで停止する。多数決・片方の代替・レビュー省略は禁止する。

| 役割 | 担当 | 禁止事項 |
| --- | --- | --- |
| 実装 | Kimi または Qwen | 自己レビュー、PR承認、マージ、品質ゲート変更 |
| 第1レビュー | Codex | 実装、自己の判定を根拠にしたマージ |
| 第2レビュー | Claude Code | 実装、自己の判定を根拠にしたマージ |
| 最終ゲート | GitHub保護ルール | 片方だけの承認でマージ |

CodexとClaude Codeは別の認証ID、別の実行環境、別の会話コンテキストを必須とする。
差分・テスト結果・Context Lockだけを渡し、Kimi/Qwenのプロンプトや自己評価をレビュー
根拠にしない。レビューの片方が実装に使われた場合、そのPRではレビュー役から外し、
別の独立レビュー環境を割り当てる。

## 監視の4レイヤー

監視を一つのBotやサービスアカウントに集中させない。すべてのレイヤーは別の実行ID、
最小権限、別々の監査ログ書込み先を使う。どの監視レイヤーにも、コード、PR、マージ、
権限、他レイヤーの設定を変更する権限を与えない。

| レイヤー | 監視対象 | 許可する操作 | 禁止する操作 |
| --- | --- | --- | --- |
| 実行監視 | 利用上限、障害、タイムアウト、退避回数 | 実行中止・順序どおりの退避要求・記録 | コード、PR、権限、品質判定の変更 |
| 品質監視 | テスト、静的解析、依存関係、秘密情報、SBOM | fail-closed判定・記録 | 実装、レビュー承認、マージ |
| 独立性監視 | 実装者とCodex・Claude Code双方の提供元、ID、実行環境の分離 | レビュー無効化・記録 | 自己レビュー、実装、マージ |
| 統制・監査監視 | Context Lock、保護ルール、App鍵、権限、監査記録 | 停止根拠の記録・異常通知 | 設定変更、秘密値閲覧、他レイヤーの上書き |

異常時は、監視レイヤー自身が修復しない。対象をfail-closedで止め、独立した修復用
変更を新規PRとして出し、通常の品質ゲートを通す。これにより、監視の検知と修復を
同じ主体に任せない。

## 常時品質ゲート

PRは次のすべてを満たすまでマージ・デプロイできない。

| ゲート | 実施主体 | 失敗時 |
| --- | --- | --- |
| Context Lock | Control Plane | 実行を開始しない |
| 決定的テスト、静的解析、依存関係・秘密情報検査 | CI | PRを失格にする |
| Codexレビュー | Kimi/Qwen実装とは別のID・実行環境 | 変更要求として停止 |
| Claude Codeレビュー | Kimi/Qwen実装とは別のID・実行環境 | 変更要求として停止 |
| レビュー実行環境監視 | READ-ONLY監視役 | マージを停止 |
| 実行AIの健全性・使用量・退避回数監視 | 実行監視レイヤー | 自動退避または停止 |
| GitHub保護ルール | GitHub | 条件未達のマージを拒否 |

実装者の自己検証は必須だが、上記の独立ゲートを代替しない。レビューAIは実装AIと
同じ提供元を使用してはならず、認証IDと実行環境も分離する。

## 監視役の必須記録

各監視レイヤーは、担当する判定についてIssue、実装AI、開始・終了時刻、失敗種別、
退避回数、テスト、レビュー、Context Lock、マージ可否を改ざん不能なActionsログと
監査ストアに記録する。
秘密値・プロンプト本文・ソースコード全量を監査ログへ保存しない。

監視役はコード、権限、秘密情報、保護ルールを変更しない。検知時はfail-closedで
対象PRを停止する。解除には新しいContext Lockと独立レビューを必要とする。

## 導入境界

この標準はルーティングと品質契約を定める。Copilot、Codex、Claude Codeの各接続用
認証情報は、個別に承認した後にSecret Managerへ格納する。実装AIに本番デプロイ、
GitHub管理、秘密情報閲覧の恒久権限を与えない。
