# 独立AIクロスレビューID標準 v1

## 目的

本標準は、AIが作成した変更を別のAIが独立にレビューするための専用IDを、
信頼できる条件でのみ導入するためのものです。レビューIDは実装者・監視役・
人間承認者と分離し、自己承認や権限横断を防ぎます。

## 導入前の必須条件

専用IDは、次のすべてが満たされるまで作成・有効化・案件インストールをしません。

1. **鍵保管先**: 承認済みの保管先があり、鍵の識別子・保管責任者・アクセス制御を記録できる。
2. **独立検証**: 発行直後に、鍵そのものを表示・転記せず、保管確認と公開鍵指紋を別経路で照合できる。
3. **失効可能性**: 紛失・所在不明・アクセス逸脱時に、即時失効と案件インストール解除を行える。
4. **最小権限**: 許可した案件だけに限定し、必要な読み取りとPRレビュー記録以外を与えない。
5. **監視**: 発行、保管確認、導入、レビュー実行、失効を監視対象として記録できる。

いずれかが未充足または証明不能なら fail-closed とする。所在不明の既存鍵は再利用しない。

## 専用IDの役割

| 項目 | 許可 | 禁止 |
| --- | --- | --- |
| 対象 | 明示的な許可リスト内のリポジトリのみ | 組織全体・全リポジトリへの横断アクセス |
| 読み取り | PR、差分、Context Lock、テスト結果 | 秘密情報、Actions secrets、環境変数 |
| 書込み | PRレビューの記録のみ | コード、ブランチ、Issue、設定、保護ルール |
| 判断 | レビュー所見・差戻し | 自己承認、マージ、デプロイ、権限変更 |

レビューIDが `APPROVED` を記録する場合でも、案件の branch protection と人間の
最終承認を置き換えません。レビュー対象、根拠、使用モデル/バージョン、実行時刻、
Context Lock ID を監査記録に残します。

## 独立性の確認

クロスレビューとして有効にするには、実装側と以下をすべて分離します。

- GitHub認証主体
- AI実行環境
- 会話コンテキストと入力経路
- 実行ログと監査記録

同じ実行者が別の表示名を使うだけ、または実装結果を同じ会話に渡して再評価するだけ
では独立性を満たしません。

## 鍵ライフサイクル

| 段階 | 必須の確認 | 未達時 |
| --- | --- | --- |
| 発行前 | 目的、権限、許可リスト、保管先、失効責任者の承認 | 発行しない |
| 発行 | 保管先への到達を確認し、指紋を独立照合 | 有効化しない |
| 導入 | 案件単位のPRと最小権限を確認 | インストールしない |
| 運用 | レビュー記録と監視ログを照合 | 停止・調査 |
| 事故 | 即時失効、インストール解除、影響確認 | 再発行前に是正 |

秘密鍵をチャット、Issue、PR、ログ、リポジトリ、環境変数表示へ出してはなりません。
詳細な保管・失効ルールは LUVIRA-SEC-001 を正とします。

## 初回導入の順序

1. 保管先と独立検証手順を人間が承認する。
2. 専用IDを最小権限で作成し、鍵保管を検証する。
3. 空の検証用リポジトリで READ-ONLY レビュー記録を確認する。
4. 監視記録と失効手順を演習する。
5. 案件ごとのPRで許可リストへ追加する。

この順序を省略して既存案件へ導入してはならない。
