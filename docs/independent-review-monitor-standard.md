# 独立クロスレビュー・監視標準 v1

## 原則

自己検証は必要条件であり、合格条件ではありません。AI または自動化が作成した
変更は、実装者と異なる主体によるクロスレビューと、独立した監視記録を通過する
まで完了扱いにしません。

## 三者分離

| 役割 | できること | できないこと |
| --- | --- | --- |
| 実装者 | 承認済み範囲の変更案・PR作成 | 自己承認、自己マージ |
| クロスレビュー者 | 仕様・差分・テスト・Context Lock を独立評価 | 実装者と同一IDでの承認、マージ |
| 監視役 | PR・レビュー・Context Lock・期限を読み取り監視し、Actions記録を残す | コード変更、マージ、権限変更、秘密情報へのアクセス |

同じ人・同じAI実行・同じ認証主体が複数の役割を兼務した場合、そのクロスレビューは
無効です。案件側の GitHub 保護ルールでは、実装者とは異なる主体の正式レビューを
必須にします。

## 必須ゲート

1. Context Lock の読み取り検証が成功していること。
2. 実装者と異なる GitHub ID による `APPROVED` レビューが存在すること。
3. レビュー者は Context Lock、仕様、差分、テスト結果、禁止事項を確認すること。
4. 監視役の READ-ONLY ワークフローが、PR作者・レビュー結果・対象PRを記録すること。
5. いずれかが欠けた場合は fail-closed とし、マージ・デプロイに進まないこと。

## AI クロスレビューの扱い

AI によるクロスレビューを採用する場合、実装 AI と異なる実行環境・認証主体・会話
コンテキストを用いる必要があります。単に同一AIへ「再レビュー」と依頼することは
独立レビューではありません。外部AIの接続は、案件ごとの承認、最小権限、
LUVIRA-SEC-001 の認証情報管理を満たす別フェーズでのみ導入できます。

v1 の共通基盤は、外部AIを接続せず GitHub の正式レビューを技術ゲートとして確認
します。これにより独立性を偽装せず、外部接続なしで fail-closed を実現します。

## 監視役の停止条件

- PR作者とレビュー者が同一
- 独立承認がない、または後から取り消された
- Context Lock が失効・不一致
- 許可外アクション、秘密情報、権限変更、保護ルール変更を検知した

監視結果は GitHub Actions の実行記録に残す。v1 の監視役は通知や変更を行わず、
停止の根拠を出力するだけとする。
