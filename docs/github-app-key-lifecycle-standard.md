# GitHub App 鍵ライフサイクル標準

GitHub App の秘密鍵は、保存しただけでは有効と扱わない。監視役は次の三段階を必ず確認する。

1. **登録完全性**: PEM の開始・終了境界、解析可能性、RSA 2048 bit 以上を確認する。不完全な値は拒否する。
2. **実利用証明**: Secret Manager から読み戻した鍵で JWT を作成し、対象 GitHub App の `/app` API へ到達できることを確認する。
3. **昇格完全性**: 本番鍵として使うのは、1 と 2 を通過した候補だけである。現行鍵の更新後も同じ実利用証明に成功しなければ、昇格は失敗として扱う。

`GitHub App key integrity monitor` は毎日この検証を実行する。失敗時は `security` / `incident` Issue を一件だけ作成し、秘密値をログ・Issue・出力に含めない。

鍵の更新は、候補鍵の検証、現行鍵への昇格、再検証、旧鍵失効の順で行う。候補検証または再検証に失敗した場合、旧鍵を失効してはならない。
