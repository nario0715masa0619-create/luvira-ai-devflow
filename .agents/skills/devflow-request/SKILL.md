# DevFlow request

## 目的

Orcaからの依頼を、実装前に人間が確認できるDevFlowの承認対象へ変換する。
Issue作成、Worker実行、PR作成、リポジトリ作成は、利用者の明示的な指示があるまで実行しない。

## 新規プロダクトの判定

利用者が新しい製品名、新規リポジトリ名、または「新しく作る」と指定した場合は、新規プロダクト受付として扱う。既存プロダクト用の実装受付に送ってはならない。

必要な情報は以下だけである。

- GitHub所有者
- 小文字・数字・ハイフンからなるリポジトリ名
- 160文字以内の製品概要
- 非公開作成であること

仕様書の実装詳細、変更許可パス、コスト上限は、新規リポジトリが `READY` になるまで実装受付へ送らない。この段階では記録用に下書きへ残すだけにする。

## 新規プロダクトの操作

1. 情報を日本語の下書きとして表示し、「新規の非公開リポジトリ作成の承認Issueだけを作る。Worker・実装PR・マージは含まない」と明記する。
2. 利用者が **送信** と明示した場合だけ、`scripts/new-project-onboarding-request.ps1` を `-Submit` 付きで実行する。外部通信の許可が必要なら、送信一回に限った許可を求める。
3. 成功時はIssue URLとproject IDだけを報告し、利用者の明示的な **承認して作成** を待つ。
4. `READY` の確認後に初めて、別の通常実装依頼として仕様書を受け付ける。自動的にWorkerやPRへ進めない。

## 既存プロダクトの操作

既存プロダクトは、台帳で `READY` のプロジェクトIDとリポジトリが一致すると確認できる場合だけ、通常の実装承認Issueを作れる。リポジトリ名を入力値だけで信用してはならない。

## 禁止

- `luvira-ai-devflow` をプロダクトコードの実装先にしない。
- 新規リポジトリ名を既存プロダクト用n8n受付へ送らない。
- 承認前にWorker・OpenCode・PR作成・リポジトリ作成を実行しない。
- mainへ直接コミットまたはマージしない。
